# CS2 Match Prediction

Predicts the winner of a Counter-Strike 2 match from recent, map-specific
player statistics, and compares four models on the task: logistic regression,
TabPFN, XGBoost and LightGBM.

The full write-up is in
[`CS2_Match_Prediction_Report.pdf`](CS2_Match_Prediction_Report.pdf)
(*"Leveraging Short-Term, Map-Specific Player Statistics for Counter-Strike 2
Match Prediction"*, April 2025, revised October 2026). Its LaTeX source is in
[`report/`](report/).

## Overview

Given a match between two 5-player teams, with each player's recent form
(kills, deaths, rating, map win-rates, etc.), the goal is to predict whether
team 1 wins.

```
  Raw HLTV match data (Kaggle)        one row per map played, stats for all 10 players
            |
            |  clean            (cs2_data.clean_raw_data)
            v
  cleaned match data                  3 missing-value variants
            |
            |  engineer features (cs2_data.build_team_features)
            v
  team_summary_statistics.csv         per-team mean / sum / std / min / max
            |
            |  train & compare
            v
  Logistic Regression · TabPFN · XGBoost · LightGBM
```

## Results

The data covers 1,010 maps from 577 professional matches (November 2023 -
January 2024). Team 1 wins 54% of maps, so that is the accuracy to beat.

| Evaluation | Two-feature LogReg | L1 LogReg | XGBoost | LightGBM |
|---|---|---|---|---|
| 30 random 80/20 splits | 70.7% / 0.79 | 70.4% / 0.79 | 72.0% / 0.80 | 71.7% / 0.80 |
| 30 splits, matches kept together | 71.5% / 0.80 | 70.8% / 0.79 | 72.6% / 0.81 | 72.1% / 0.80 |
| Train on older, test on newest 20% | 69.4% / 0.80 | 73.8% / 0.81 | 74.4% / 0.83 | 73.1% / 0.83 |

*Accuracy / ROC AUC. Standard deviation across splits is 2-3 points.*

What this shows:

- **The models predict about 72% of maps correctly (AUC 0.80),** and the result
  holds when predicting newer matches from older ones.
- **A simple baseline gets most of the way.** A logistic regression on just two
  features, the difference in team Rating 2.0 and in map win-rate, is within
  about a point of the 142-feature models on repeated splits; the full feature
  set adds about four points on the forward-in-time split.
- **A single test split is noisy.** XGBoost's accuracy ranges from 65% to 78%
  across the 30 random splits, so the gaps between models in any one split
  are not meaningful.
- **Feature pruning does not help once it is done properly.** The original
  report's best result (pruned LightGBM, 79.7%) chose features using the test
  set. Choosing them on training data only gives 71.9% / 0.81, no better than
  the unpruned model.
- TabPFN is competitive without any hyperparameter tuning, and the models
  broadly agree on which features matter most: map win-rates, K/D ratio,
  deaths per round and recent rating.

These numbers come from [`robustness_check.py`](robustness_check.py); the
notebook shows one split in detail.

## Repository structure

| File | Description |
|------|-------------|
| [`CS2_Match_Prediction.ipynb`](CS2_Match_Prediction.ipynb) | Main notebook: data preparation, feature engineering, training and comparison of all four models. |
| [`cs2_data.py`](cs2_data.py) | Data pipeline: download, cleaning, feature engineering, train/test split. |
| [`cs2_eval.py`](cs2_eval.py) | Evaluation: metrics and plots (ROC, precision-recall, confusion matrix). |
| [`robustness_check.py`](robustness_check.py) | Re-scores the models over repeated, grouped and forward-in-time splits, against a two-feature baseline, and with leakage-free feature pruning. Produces the Results table above. |
| [`CS2_Match_Prediction_Report.pdf`](CS2_Match_Prediction_Report.pdf) | The written report. |
| [`report/`](report/) | LaTeX source and figures for the report. |
| `team_summary_statistics.csv` | Ready-to-model feature table (1,010 maps), generated by the pipeline and included so the notebook runs out of the box. |

## Setup

Python 3.10+ recommended.

```bash
pip install -r requirements.txt
```

A GPU is optional; it speeds up TabPFN, but everything runs on CPU.

## Usage

Open `CS2_Match_Prediction.ipynb` and run it top to bottom. The processed data
is included, so Section 1 (the Kaggle download and rebuild) can be skipped.

To reproduce the Results table (a few minutes on CPU):

```bash
python robustness_check.py
```

## Data

Source: [Counter-Strike 2 HLTV match data](https://www.kaggle.com/datasets/victorpicinin/counter-strike-2-hltv-match-data)
on Kaggle. Re-downloading it (optional, only needed to rebuild the dataset from
scratch) requires the `kagglehub` package and Kaggle credentials.
